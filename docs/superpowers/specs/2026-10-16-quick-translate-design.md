# 快捷翻译桌面应用设计

## 1. 目标与范围

这是一个 Windows 优先、保留跨平台扩展能力的个人桌面翻译工具。它提供两条主要入口：

1. 通过全局快捷键框选屏幕区域，执行 OCR 并翻译。
2. 通过常驻/按需打开的小窗口输入或粘贴文本并翻译。

第一版支持源语言和目标语言手动选择，并记住最近设置；翻译引擎支持在线、本地和多个用户配置的服务商；保存最近翻译记录。第一版不包含账号系统、云端同步、团队协作或自动翻译整页网页。

## 2. 设计原则

- 快：快捷键触发后尽快出现截图框选，译文结果可直接复制。
- 可控：用户明确选择是否使用在线服务，敏感文本不默认写入日志或上传到非预期 provider。
- 可替换：OCR、翻译 provider 和平台能力通过接口隔离。
- 可恢复：网络、OCR、provider 限额或配置错误时，界面提供可理解的错误和替代操作。
- Windows 优先：第一版充分利用 Windows 能力，但核心领域逻辑不依赖 Windows API。

## 3. 推荐技术路线

- 桌面壳：Tauri 2。
- UI：TypeScript + React，负责小窗口、设置、历史记录和结果浮窗。
- 系统能力：Rust，负责全局快捷键、系统托盘、截图、剪贴板、窗口管理和安全存储桥接。
- OCR：第一版优先使用 Windows 原生 OCR 适配器；保留 Tesseract/PaddleOCR 适配器接口作为跨平台或离线 fallback。
- 翻译：定义统一 TranslationProvider 接口。内置免配置 provider（例如 MyMemory 或用户指定的 LibreTranslate 实例），并支持用户配置的 DeepL、Google、Microsoft、OpenAI 兼容接口等 provider。
- 本地引擎：通过 LocalTranslationProvider 接入本机引擎；具体模型/运行时作为可选安装项，不强制进入首个安装包。
- 配置与历史：本地 JSON/SQLite 均可；MVP 使用 SQLite 保存结构化历史，配置放在系统应用数据目录。
- 密钥：Windows Credential Manager；跨平台时使用各系统原生钥匙串。

## 4. 模块边界

### 4.1 平台适配层

对外提供 `GlobalShortcut`、`ScreenCapture`、`Clipboard`、`Tray`、`SecureStore` 接口。Windows 实现放在 Rust 平台模块中，未来增加 macOS/Linux 实现时不改变上层业务接口。

### 4.2 OCR 服务

输入截图区域，输出带置信度的文本和可选文本块坐标。OCR 服务负责超时、空结果和语言包缺失的错误转换，不负责翻译。

### 4.3 翻译服务

统一接口接收源语言、目标语言、文本和 provider 配置，返回译文、provider 标识、耗时和可选用量信息。路由器根据用户选择执行在线、本地或 fallback provider；provider 自己处理认证、限流和响应格式转换。

### 4.4 应用状态

维护当前语言对、provider、窗口状态、最近任务和错误状态。UI 不直接调用外部 provider，而是通过 Tauri command/事件与 Rust 服务通信。

### 4.5 UI

- 快捷翻译浮窗：展示 OCR 原文、译文、复制按钮、重试和切换 provider。
- 手动翻译窗口：输入区、语言选择、翻译按钮、结果区和历史入口。
- 设置窗口：provider 管理、默认语言对、快捷键、在线/本地隐私策略。
- 历史列表：按时间显示摘要，支持重新打开和删除。

## 5. 数据流

### 截图翻译

`全局快捷键 -> 截图选区 -> OCR -> 原文确认/修正 -> provider 路由 -> 结果浮窗 -> 复制或写入历史`

如果 OCR 为空，停止在结果阶段并提示重新框选；如果在线 provider 失败且本地 provider 可用，按隐私策略提示或自动 fallback；如果所有 provider 失败，保留 OCR 原文并允许复制。

### 手动翻译

`输入文本 -> 语言校验 -> provider 路由 -> 结果展示 -> 复制/重试/写入历史`

输入文本只在用户发起翻译时发送。历史记录默认保存原文、译文、语言对、provider 和时间；设置中提供关闭历史或一键清空。

## 6. 在线/本地策略

- 默认模式为“在线优先，本地可用时 fallback”，首次使用时明确展示当前 provider。
- “敏感内容”模式下只允许本地 provider；若本地引擎不可用，阻止上传并给出安装/配置提示。
- 免费免配置 provider 必须显示服务名和可能的限额/不稳定提示。
- API Key 不出现在 UI 日志、异常信息或历史记录中。
- 网络请求设置连接和总超时，错误分类为认证失败、限流、网络不可用、服务错误和响应格式错误。

## 7. MVP 验收标准

1. Windows 上可用一个全局快捷键打开框选截图。
2. 框选英文或中文图片后，OCR 能生成可编辑原文；空结果有明确提示。
3. 用户可以选择源语言和目标语言，应用重启后保留选择。
4. 至少一个免配置在线 provider 和一个用户配置 provider 可用；provider 可切换。
5. 小窗口可输入文本、翻译、复制结果，并显示错误状态。
6. API Key 使用系统安全存储，不写入明文配置或日志。
7. 最近记录可查看、重新翻译、删除；用户可关闭历史记录。
8. 网络不可用时，若本地 provider 已配置，可完成翻译；否则显示可恢复提示。
9. 核心逻辑测试覆盖 provider 路由、错误分类、配置持久化和历史记录；Windows 平台能力至少有手工验收步骤。

## 8. 非目标与后续方向

首版不做实时屏幕翻译、批量文档翻译、浏览器插件、云端同步、自动检测并替换原文、复杂术语库和账号体系。后续可增加 OCR 结果区域重选、快捷复制译文回原应用、术语表、批量文件翻译以及 macOS/Linux 平台适配。

## 9. 主要风险与缓解

- 免费 provider 不稳定：provider 抽象、超时重试、可配置备用 provider。
- 本地 OCR/翻译安装包过大：核心包保持轻量，模型和运行时按需安装。
- 截图可能包含敏感信息：清晰的在线/本地模式、敏感模式和不记录历史选项。
- 跨平台差异：将平台能力限制在适配层，领域逻辑保持 TypeScript/Rust 通用。
- OCR 误识别：结果浮窗提供原文编辑和重新翻译入口。
